# Story 2.2: Sections About, Experience & Freelance Engagements

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a visitor (VP Engineering),
I want an "about" section (positioning: architecture, design systems, performance, leadership), an "experience" section listing roles, and a "freelance engagements" section listing missions — each entry with the relevant company/mission, title, dates, duration, status, KPIs/highlights, tech tags (and outbound URL for missions),
so that I can judge depth, leadership, and delivery track record in one read.

## Acceptance Criteria

1. **Section About (`01 — About`) — corps 2 colonnes depuis le contenu typé.** Étant donné la section `about`, quand elle est rendue sur desktop, alors elle affiche un **corps sur 2 colonnes** (`dict.sections.about.body.left` à gauche, `dict.sections.about.body.right` à droite — paragraphes empilés dans chaque colonne) véhiculant le positionnement (architecture / craft + leadership distribué), et **reflowe en 1 colonne** sous le palier `sm`. Le `SectionHead` (label numéroté `01` + heading Cormorant + sous-titre) est déjà câblé par la page (Story 1.3) — cette story ajoute le **corps** sous lui. Toutes les chaînes visibles viennent du module de contenu typé dans la locale active — aucune chaîne codée en dur (les glyphes ASCII décoratifs `$`, `→`, `↗`, `·`, numéros `01 /` restent tolérés en dur). (FR2, FR19, FR33, FR34, NFR12, NFR20.)
2. **Section Experience (`02 — Experience`) — rôles en `<article>` sémantiques, rangée de KPI, bullets, tags, reflow.** Étant donné la section `experience`, quand elle est rendue, alors **chaque rôle** (`dict.sections.experience.roles[]`) est un **`<article>` sémantique** affichant : entreprise (`company`), lieu (`location`), intitulé (`title`), dates (`dates`), durée (`duration`), une **rangée de KPI bien visibles** (`role.kpis[]` → `{value, label}`, ex. « 3,000+ companies », « 5 devs hired & onboarded », « 2 MB WeChat bundle cap »), des **bullets de faits marquants** (`role.bullets[]`), et des **tags technologiques** (`role.tags[]`). Le `<h3>` du rôle ≠ le `<h1>` du hero (un seul `<h1>` sur la page — celui du hero). La mise en page **reflowe proprement** du mobile (~375px) au desktop **sans débordement horizontal**. (FR3, FR33, FR34, NFR12.)
3. **Section Freelance Engagements (`03 — Freelance Engagements`) — `MissionCard`, missions en `<article>`, statut, URL sortante, tagline, bullets, tags, reflow.** Étant donné la section `freelance` et le composant `MissionCard`, quand elle est rendue, alors **chaque mission** (`dict.sections.freelance.missions[]`) est un **`<article>` sémantique** affichant : nom (`name`), intitulé (`title`), dates (`dates`), durée (`duration`), **statut** (`status`, ex. « Completed » / « Shipped to production » ; FR : « Terminée » / « Mise en production »), une **URL sortante** (`url`, ex. `sayelo.ai`, `penpaloo.io` → lien `<a href="https://{url}" target="_blank" rel="noopener noreferrer">` avec le glyphe `↗`/`→` `aria-hidden`, cohérent avec le pattern lien sortant du hero), une **tagline** (`tagline`), des **bullets** (`bullets[]`), et des **tags technologiques** (`tags[]`). La section reflowe proprement du mobile au desktop **sans débordement horizontal**. *(Le composant `location` est présent dans le dictionnaire mais facultatif à l'affichage — l'afficher si tu suis le pattern `RoleCard`, ou l'omettre ; rester cohérent. Pas de rangée de KPI sur les missions.)* (FR3a, FR33, FR34, NFR12, UX-DR21.)
4. **Numérotation des labels de section cohérente nav ↔ `SectionHead`.** Étant donné la page d'accueil, quand elle est rendue, alors la numérotation des sections suit `01 About · 02 Experience · 03 Freelance Engagements · 04 Side Projects · 05 Stack · 06 Contact`, **de façon cohérente** dans les ancres de nav **et** dans les labels de `SectionHead`. *(Déjà garanti par le modèle de contenu typé de la Story 1.3 — `dict.sections.*.num`/`navLabel`/`label` — et par `Nav` qui dérive ses liens de `Object.values(sections)`. Cette AC est une **vérification de non-régression**, pas un nouveau travail : ne pas renuméroter ni réordonner.)* (FR3a, FR11, FR33.)
5. **Pré-rendu statique préservé, zéro régression, responsive propre.** Étant donné la page d'accueil, quand `npm run build` tourne, alors `/en` et `/fr` restent **pré-rendues en statique** (`dynamicParams = false`), aucun composant nouveau n'introduit de `'use client'` (`About`, `Experience`, `RoleCard`, `FreelanceEngagements`, `MissionCard` sont des **Server Components** — aucune interactivité), `npm run typecheck` et `npm run lint` passent, et le shell de la Story 1.3 + le hero/marquee de la Story 2.1 (Nav, scroll-spy, ancres, Footer, i18n FR/EN, sélecteur de langue, `Hero`, `Clients`, `AvailabilityBadge`) restent fonctionnels. À ~375px : reflow propre des 3 sections (corps about 1 colonne, KPI 1 colonne, tags `flex-wrap`), tap targets des liens ≥ 44px, **aucun scroll horizontal** sur toute la page. Aucune animation ici (le fondu au défilement = Epic 3 / Story 3.1). (NFR3, NFR4, NFR6, NFR12, NFR16.)

### Patterns d'architecture & garde-fous

- **Server Components par défaut.** `About`, `Experience`, `RoleCard`, `FreelanceEngagements`, `MissionCard` n'ont **aucune** interactivité ⇒ **pas** de `'use client'`.
