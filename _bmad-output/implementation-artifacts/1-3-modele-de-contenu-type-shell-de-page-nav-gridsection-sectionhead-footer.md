# Story 1.3: Modèle de contenu typé & shell de page (Nav / GridSection / SectionHead / Footer)

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a visitor,
I want a persistent terminal-style navigation (section anchors, version badge, availability badge, email CTA, CV link, language switcher) and a footer, on a statically pre-rendered home page,
so that I can move around the site and contact Michael from anywhere, immediately.

## Acceptance Criteria

1. **Modèle de contenu typé, complet FR/EN, séparé de la présentation.** Étant donné un module de contenu typé couvrant **toutes les sections** (`meta`, `hero`, `clients`, `about`, `experience`, `freelance`, `projects` [side projects], `stack`, `ai`, `contact`, `footer`) en **FR et EN**, quand l'app build, alors **toutes** les données de section proviennent de ce module, il est **entièrement typé**, **séparé de la présentation** (modifier le contenu ne requiert aucune modification d'un composant de présentation), et les **deux locales sont complètes** — une clé manquante / en trop / mal typée dans `fr` casse `npm run typecheck` (donc la CI), via le pattern établi en 1.2b (`en.ts` = source de vérité ⇒ `type Dictionary = typeof en` ⇒ `fr.ts … satisfies Dictionary`). Le contenu est extrait des sources de design : **`content.md` est la source faisant autorité** (texte, structure, numérotation des sections, missions freelance) ; **`content.js`** la complète pour les données structurées que `content.md` n'expose pas en clair (rangées de KPI des rôles d'expérience, `project_meta` de Maqom, groupes de la section `stack`). Numérotation des sections (issue de `content.md`) : `01 About · 02 Experience · 03 Freelance Engagements · 04 Side Projects · 05 Stack · 06 Contact` ; la section « AI & Agentic Engineering » n'est pas numérotée ; `hero` (label `00`) et le marquee `clients` ne sont pas des cibles de navigation. (Note de portée : le **modèle est rempli intégralement ici** — EN repris fidèlement des sources, FR en traduction soignée ; la **relecture/finition finale du contenu FR** est la Story 2.4. Les **sections de page réelles** — layouts hero/about/cartes/marquee/etc. — restent l'Epic 2 ; ici on ne livre que le **shell**.)

2. **Page d'accueil statiquement pré-rendue.** Étant donné la route de la page d'accueil (`app/[locale]/page.tsx`, déjà migrée sous `[locale]/` en 1.2b), quand elle est requise, alors elle est **statiquement pré-rendue** (HTML complet dans la réponse initiale, lisible sans JavaScript) — `generateStaticParams` + `dynamicParams = false` conservés (root layout), aucun `headers()` / `cookies()` / `fetch` runtime introduit dans les pages/layouts ; les composants client (`Nav` interactif, sélecteur de langue) sont SSR puis hydratés (acceptable — ne casse pas le SSG des pages).

3. **Composant `Nav`.** Étant donné le composant `Nav`, quand je consulte n'importe quelle partie du site sur desktop ou mobile, alors la nav est **persistante** (sticky `top-0`, z-index élevé), de style « terminal » (p.ex. `$ cd ./about`), affiche un **badge de version** (p.ex. `v2026.1`) et un **badge de disponibilité** (p.ex. `available — Q2 2026`) — **les deux textes de libellé proviennent du module de contenu typé, pas codés en dur** —, comporte des **liens d'ancrage vers chaque section** (`#about`, `#experience`, … construits depuis la liste de sections du module de contenu) avec `aria-current` sur la section active (scroll-spy `IntersectionObserver`), expose un **CTA email** (`mailto:` vers l'adresse du module de contenu) et un **lien de téléchargement du CV**, et inclut le **sélecteur de langue visible** (le composant `LanguageSwitcher` livré en 1.2b est monté ici — il était provisoirement dans `page.tsx`). **Et** la nav utilise `backdrop-filter` blur avec une **dégradation gracieuse** quand non supporté (fond plus opaque en repli, layout intact). **Et** la nav reste pleinement utilisable de ~375px aux grands écrans : les liens de section reflowent (menu repliable / barre dédiée — au choix), tap targets ≥ 44px, aucun débordement horizontal.

4. **Asset CV servi à un chemin stable.** Étant donné un fichier CV (PDF) commité dans le dépôt (sous `public/`), quand le site build, alors un **fichier CV téléchargeable** est servi à un **chemin stable** (p.ex. `/cv/michael-mann-cv.pdf`), le **lien CV de la nav pointe dessus et le télécharge correctement** (attribut `download`), et ce chemin est **référencé depuis le module de contenu** (un seul point de vérité) pour que les liens CV du hero/contact (Epic 2) réutilisent la même valeur. (Le **vrai** PDF de CV sera substitué en Epic 2 — FR25 ; ici un PDF *placeholder* est acceptable, du moment que le câblage et le chemin sont définitifs.)

5. **Composants `GridSection`, `SectionHead`, `Footer`.** Étant donné les composants `GridSection`, `SectionHead` et `Footer`, quand les sections sont rendues, alors : **`GridSection`** fournit la **grille de fond décorative** (rails latéraux bordés ~32px, bordure inférieure de section, label monospace de section pivoté `{idx} ↗ {LABEL}` en `aria-hidden`) et les **paddings responsive** (tokens `--spacing-section-*` desktop, variantes mobile réduites) — avec une variante de fond (`bg-bg` / `bg-bg-alt` / `bg-bg-alt2` pour `clients` / `ai`) ; **`SectionHead`** rend un **label numéroté monospace** (`idx` en accent + libellé) + un **titre `<h2>` en Cormorant** + un **sous-titre** (gris muted), réutilisé par toutes les sections ; **`Footer`** affiche la **ligne de copyright** (issue du module de contenu) collée en bas de page (`mt-auto` — le `<body>` est déjà `min-h-full flex flex-col`).

> **Note de portée — ce que cette story livre :** le **modèle de contenu typé complet** (extension du dictionnaire FR/EN de 1.2b avec toutes les sections, garde de complétude conservée) + les **composants de shell** `Nav` / `GridSection` / `SectionHead` / `Footer` (+ une marque `MMLogo` SVG inline, + un éventuel hook `useActiveSection`) + le **montage du shell sur la page d'accueil** (`Nav` en tête, des `GridSection` « coquilles » — `id` d'ancrage + `SectionHead` — pour chaque section de contenu, `Footer` en pied) + l'**asset CV** servi et câblé dans la nav + le **déplacement du `LanguageSwitcher`** de `page.tsx` vers `Nav`. **Hors scope (ne PAS faire ici) :** le **contenu réel des sections** (layout du hero, meta strip, cartes de rôle, rangées de KPI, marquee animé, cartes terminal des projets, cartes AI, carte de contact, etc.) → **Epic 2** (les `GridSection` de 1.3 sont des coquilles vides ou quasi — Epic 2 remplit les corps) ; le **curseur personnalisé**, le **fondu au défilement**, l'**animation du marquee** → **Epic 3** ; le **SEO complet** (OpenGraph/Twitter, JSON-LD `Person`, `sitemap.xml`, `robots.txt`, finition `hreflang`/canonical multi-pages, pipeline favicon/OG/manifest depuis les assets de marque) → **Story 4.3** ; le **skip-link**, l'audit clavier/ARIA exhaustif, la correction de contraste des tokens (`#666` → `#888`) → **Epic 4 / Story 4.1** ; l'**analytics** → Epic 5 ; le **blog** → Epic 6 ; le **vrai PDF de CV** → substitué en Epic 2 ; la **relecture/finition du contenu FR + finition responsive transverse** → Story 2.4. Ne pas sur-construire : pas d'internals de section réels, pas d'animations, pas d'images hormis le SVG inline de la marque `MM`. Pas de nouvelle dépendance npm, pas de lib i18n, pas de `tailwind.config.js`, pas de shadcn/ui.

### Garde de complétude des traductions (FR19 / AC#1) — pattern à conserver
